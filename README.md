# Legit Assets — компактна Telegram Mini App

Основний код об'єднано у п'ять файлів:

- `src/ui.tsx`: інтерфейс, компоненти, профіль, екскурсія, каталог, адмінка та клієнтські хуки.
- `src/shared.tsx`: переклади, навігація, точні розрахунки та спільні типи.
- `src/server.tsx`: авторизація, бізнес-логіка, постачальники, оплати, бот і NFT.
- `src/api.ts`: усі HTTP-обробники. `src/app/api/[...path]/route.ts` зберігає старі адреси API.
- `src/views.tsx`: серверні представлення каталогу й інформаційних сторінок.

`assets.pack.json` містить усі 193 початкові зображення й анімації без зміни байтів. Їхні URL збережено. Невеликі файли `page.tsx`, layout та модальні маршрути залишено для сумісності Next.js. Код не заховано у ZIP-рядках і не відновлюється в сотні файлів перед запуском: це справжня консолідація TypeScript. Коментарі та namespaces позначають попередні модулі.

## Спрощені налаштування

Бот **@LegitAssetsBot** заданий у коді: окремо вводити його username не потрібно. Прибрано старе створення адміністратора через email/пароль і окрему реєстрацію Telegram-вебхука Mini App. `ADMIN_BOOTSTRAP_EMAIL`, `ADMIN_BOOTSTRAP_PASSWORD`, `BOT_UPDATE_OWNER`, `NEXT_PUBLIC_BOT_USERNAME` та `BOT_WEBHOOK_ENABLED` не потрібно додавати у Railway.

Вхід адміністратора залишається через підписаний Telegram-вхід та `ADMIN_ID`. Monobank налаштовується у Python-боті. Приватні секрети для зв'язку бота й Mini App залишаються потрібними; їх можна згенерувати одним викликом:

```bash
npm run env:init -- --domain=your-domain.com
```

Це створює локальний `.env` із різними випадковими ключами, не перезаписуючи наявний файл. Для Railway перенесіть значення з цього файлу в Variables через Raw Editor. `DATABASE_URL` у Railway візьміть зі свого PostgreSQL-сервісу: автоматична адреса `db:5432` призначена лише для Docker Compose. Токен наявного бота та API-ключі сервісів заповнюються власними значеннями. `BOT_WEBHOOK_SECRET` та `BOT_BRIDGE_SECRET` мають збігатися з відповідними значеннями Python-бота; не змінюйте їх лише на одному сервері.

## Запуск

Потрібні Node.js 22.18+ та PostgreSQL. Збережіть стару базу й резервну копію перед міграціями.

```bash
npm ci
cp .env.example .env
# Заповніть .env власними параметрами.
npm run db:generate
npm run db:deploy
npm test
npm run typecheck
npm run build
npm start
```

У `.env` задайте `DATABASE_URL`, `NEXT_PUBLIC_SITE_URL` (ваша публічна HTTPS-адреса), `BOT_TOKEN` та решту параметрів сервісів. Наявні дані PostgreSQL не переносіть у нову порожню базу: застосовуйте міграції до наявної. Нова міграція `20261013045000_nft_checkout` додає таблиці доказу гаманця та NFT-замовлень, не змінюючи балансів.

## Реальна купівля NFT за GRAM

Підключено офіційні `GET /v1/nfts/{address}/` і `POST /v1/nfts/buy/` Marketapp. Потрібен ваш серверний `MARKETAPP_API_TOKEN` із доступом до платного NFT API. Для стабільної перевірки блокчейну задайте `TONCENTER_API_KEY`. Токени не передаються браузеру. У документації Marketapp: https://api.marketapp.org/docs/.

1. Пройти перший вибір мови та екскурсію.
2. Обрати **живий** NFT. SVG-фолбек позначено демонстраційним і купівля з нього не запускається.
3. Натиснути «Підтвердити гаманець» та погодити `ton_proof`. Потрібен основний блокчейн; ця версія перевіряє ключ уже активованого гаманця через `get_public_key`. Для свіжого неактивованого гаманця спершу активуйте його у застосунку гаманця.
4. Натиснути «Підтвердити купівлю». Сервер повторно перевіряє поточну ціну, валюту GRAM/TON (назви нативної монети), строк транзакції та поточного власника. USDT для NFT відхиляється. Гаманець показує й підписує реальну транзакцію купівлі.
5. Сервер перевіряє власника **та успішну транзакцію transfer** потрібного NFT від попереднього власника до підтвердженого покупця. Хеш транзакції видачі унікальний: одна передача не створює повторних оплат.
6. Після видачі — окреме підтвердження збору 7% на магазин `UQBhos7uoI_1Fs4HCUWUEqv3ZVwKb_EWuHeOO7LMH2t34Wwl`. Повна ціна товару дорівнює базі + 7%; мережеві витрати окремо показує гаманець. Збір не стягується до видачі. Гаманець запитає два підписи, а не один.
7. «Оплату завершено» з'являється лише після підтвердження у блокчейні надходження збору: перевіряються адреси, сума, час, коментар замовлення та унікальний хеш. Повторний запуск збору захищено п'ятихвилинною серверною блокіровкою. Якщо підпис відхилено, дочекайтеся завершення цього строку перед новою спробою.

Продовжити незавершене NFT-замовлення можна з **Історії**. Непідписаний/прострочений запит не позначається оплаченим. Після прострочення перевірте отримання перед створенням нового запиту. Демонстраційна кнопка, BOC-відповідь гаманця або клієнтський POST самі по собі не підтверджують видачу/оплату. Приватні ключі/seed гаманця магазину не потрібні: покупець підписує покупку сам.

Важлива межа: прямий NFT-checkout видає NFT у гаманець покупця; він не списує GRAM зі старого внутрішнього балансу Python-бота. 7% — окремий платіж після видачі. Якщо покупець не завершує збір, NFT уже належить йому, а замовлення має статус «збір очікує оплати». Код не обіцяє атомарного стягнення двох платежів або автоматичного показу on-chain NFT у Telegram-профілі.

## Профіль і поповнення через бота та Monobank

Збережено чотири вкладки: Магазин, NFT, Історія, Профіль. Вибір мови й одноразова екскурсія зберігаються в PostgreSQL. Завантаження/видалення фото: PNG/JPEG/WebP до 2 МБ, серверні 256×256 WebP без метаданих. Усі попередні категорії, SMM, адмінка, CloudStorage, Safe Areas, Telegram-тема та ефекти натискання збережено.

Поповнення відкриває Python-бота `miniapp_topup_uk/ru/en`. Баланс UAH/GRAM береться з його наявної SQLite-бази. Mini App не створює другий зарахувач коштів. Використовуйте вже наданий `legit-bot-integrated.zip` та його `MINIAPP-INTEGRATION-UA.md` для Monobank. Не запускайте старий Monobank relay одночасно з новим обробником.

На обох серверах — однакові окремі `BOT_WEBHOOK_SECRET` та `BOT_BRIDGE_SECRET` від 32 символів. Python-бот є єдиним отримувачем Telegram-оновлень; `BOT_BRIDGE_URL=https://BOT-DOMAIN` проксує читання `/balance`. Telegram-оновлення приймає Python-бот, передаючи тільки події Mini App до `/api/bot/webhook`. API-адреси після консолідації збережено.

## Редагування зображень

```bash
node scripts/assets.mjs extract
# Відредагуйте assets-edit; ця тимчасова папка потрібна лише для редагування.
node scripts/assets.mjs pack
npm run build
```

На робочому сервері достатньо одного `assets.pack.json`; витягувати картинки для запуску не потрібно. Після пакування можна прибрати лише тимчасову папку `assets-edit`.

## Перевірки та межі

55 попередніх тестів + 6 NFT-тестів + 1 тест пакета зображень: **62/62**, усі початкові 30 тестів збережено. TypeScript strict і production-збірка проходять. Профіль, фото, онбординг, вкладки й категорії перевірено у браузері на ширинах 320/390/430. Окремий браузерний сценарій через справжній TON Connect SDK із синтетичним injected-гаманцем пройшов: ton_proof → підпис купівлі → видача → блокіровка збору → підпис збору → завершення. Приватні маркери чотирьох серверних параметрів перевірено на відсутність у клієнтській збірці. JSON-пакет має лише дозволені публічні ресурси, без вихідного коду, БД чи секретів.

Тести використовують синтетичний гаманець, відповіді API та підтвердження блокчейну. Справжні платежі не виконувалися, робоча БД не запускалася й ваші реальні токени не налаштовувалися. Це готовий код шляху покупки, а не доказ проведеної живої угоди. Після налаштування потрібен контрольний сценарій на вашому сервері з вашим гаманцем. Комерційні ключі й доступ до платного API потрібно надати власнику магазину.
