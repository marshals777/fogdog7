# Legit Assets v17 — 5 файлів для Railway

Повний Mini App, клієнт, адмінка, SQLite, каталог, ілюстрації та тести. Код попередньої версії збережено побайтово в app.pack.json; він не скорочений і не мінімізований. Пакет приватний, браузеру не віддається.

## Деплой

1. Завантажте **всі 5 файлів** із цієї папки в корінь GitHub-репозиторію. Створіть Railway Service з репозиторію. Якщо лишили вкладену папку legit-assets-miniapp, виберіть її як Root Directory. Видаліть старі ручні Build/Start/Pre-deploy Commands: використовується кореневий Dockerfile і railway.json.
2. Додайте цьому сервісу **один Volume з Mount Path `/data`**. Окремий PostgreSQL не потрібен. Залиште одну репліку.
3. Variables: додайте **BOT_TOKEN** вашого @LegitAssetsBot і **ADMIN_ID** — власний числовий Telegram ID. Для реальних товарів також додайте потрібні ключі: MARKETAPP_API_TOKEN, LZT_TOKEN, SMM_API_KEY; TONCENTER_API_KEY рекомендований. Ключі не вставляйте у файли репозиторію.
4. Networking → Generate Domain. Railway передає домен автоматично; NEXT_PUBLIC_SITE_URL вручну потрібен лише для іншого власного домену. Запустіть Deploy.
5. У BotFather призначте HTTPS-домен кнопці запуску Mini App для @LegitAssetsBot.

Налаштування Docker, healthcheck і перезапуску вже задані. При першому старті створюються SQLite, таблиці, каталог та внутрішні ключі; запускається worker. Додаткові Build/Start Commands і команди генерації секретів для нового магазину не потрібні.

Це **5 файлів у ZIP та GitHub**. У контейнері автоматично створюється .runtime з файлами, потрібними Next.js/Prisma, і встановлюються залежності. Без робочих файлів ці інструменти не запускаються.

## Уже є магазин із базою?

Збережіть той самий Volume, BOT_TOKEN, ADMIN_ID, ключі постачальників та **старий DELIVERY_ENCRYPTION_KEY**. При переході зі старої версії також збережіть INTERNAL_API_SECRET і CRON_SECRET, якщо вони використовуються зовнішніми інтеграціями. Приберіть старі PostgreSQL DATABASE_URL/DIRECT_URL. Доступні дані PostgreSQL автоматично не переносяться; не видаляйте стару БД із реальними покупками.

Новий магазин автоматично зберігає 3 внутрішні ключі у `/data/miniapp-secrets.json` із правами 0600. Наступні деплої використовують їх повторно. Якщо база існує, а ключ шифрування відсутній, запуск зупиниться, щоб не створити інший ключ для старих товарів. Пошкоджений файл секретів також не замінюється автоматично.

Бекап потребує і SQLite, і miniapp-secrets.json. Копії тримайте приватними, поза робочим Volume. Не видаляйте файл секретів при очищенні тимчасових даних.

## Реальні покупки й поповнення

Без ключів постачальників інтерфейс працює, але автоматичні закупівлі відповідних товарів недоступні. NFT-фолбек позначений як демонстраційний. Для LZT/SMM після перевірки постачальника ввімкніть MARKET_LIVE_ORDERS_ENABLED=true / SMM_LIVE_ORDERS_ENABLED=true. Для SMM потрібна також схвалена карта послуг. Повна інструкція попередньої версії збережена у .runtime/README.md.

Ваш Python-бот та Monobank залишаються окремими. Для показу його балансу в Mini App задайте BOT_BRIDGE_URL і спільний BOT_BRIDGE_SECRET. BOT_WEBHOOK_SECRET та інші секрети зв'язку мають відповідати налаштуванням бота. Ці значення не генеруються навмання на двох сервісах: вони повинні збігатися. Готовий ZIP не реєструє банківський webhook і не деплоїть окремий бот.

Вхід адміністратора — з дозволеного Telegram-акаунта через профіль Mini App. Перший вхід клієнта: вибір мови → екскурсія → магазин. NFT — окремий розділ з оплатою GRAM. Кошик/обране й порожні неактивні профілі очищуються за правилами 72 годин; фінансові записи зберігаються.

## Локальні команди, Node.js 22.18+

```bash
node boot.mjs install
node boot.mjs build
node --env-file=/absolute/path/private.env boot.mjs start
node boot.mjs run verify
node boot.mjs run test:launch
node boot.mjs run db:backup -- /absolute/private/backup.sqlite
```

Файл private.env — ваш приватний файл змінних, зокрема BOT_TOKEN і NEXT_PUBLIC_SITE_URL для запуску поза Railway. Його не потрібно завантажувати в GitHub. Для verify/test:launch достатньо встановлених залежностей; тест запуску використовує власну тимчасову БД і тестові Telegram-підписи, без реальних оплат.

Для редагування: `node boot.mjs unpack`, відкрийте .runtime/src. Якщо змінювали відновлені маршрути/тести, спершу виконайте в .runtime `npm run source:pack`; після будь-яких змін виконайте з кореня `node boot.mjs pack`. Це збере весь код назад в один app.pack.json. У GitHub відправляйте ті самі 5 файлів; .runtime не завантажуйте.

Перевірки на локальному сервері не замінюють контрольної реальної покупки після підключення ваших ключів і бота. Доступу до вашого Railway-акаунта цей комплект не потребує.

## Перевірено у v17

- Усі 20 вихідних файлів v16 збережені в пакеті побайтово; вкладені 29 файлів та всі ресурси також залишилися без скорочення.
- 106 тестів, TypeScript, production-збірка й аудит клієнтських ресурсів пройшли.
- Production-сервер: Telegram-вхід клієнта/адміна, мова/екскурсія, вихід, закриті admin API, автоматична SQLite та повторний запуск.
- Новий boot.mjs: запуск без заданих внутрішніх секретів, створення БД/каталогу, збереження користувача й тих самих секретів після перезапуску. Перевірено відмову при пошкодженому файлі секретів, іншому ключі шифрування та відсутньому Volume на Railway.
- Docker-образ і ваш Railway-акаунт тут не запускалися. Перевірки виконані локальним Node.js; реальні NFT/Monobank-платежі потребують окремої перевірки з вашими ключами.
